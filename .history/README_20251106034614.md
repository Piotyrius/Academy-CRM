# Academy CRM Backend

A comprehensive Django REST API backend for managing a private academy in Batumi, Georgia.

## Features

- **User Management**: Role-based access control (Admin, Lecturer, Student) with JWT authentication
- **Catalog Management**: Programs, Courses, Cohorts, and Sessions with recurring schedule generation
- **Admissions**: Online applications, enrollment management with capacity checks
- **Attendance Tracking**: Bulk attendance marking optimized for 20-30 students
- **Assessments & Grading**: Exams, quizzes, projects with weighted grades
- **Certificates**: PDF generation with QR codes for verification
- **Student Portal**: Read-only API endpoints for students to view their data
- **Reporting**: CSV exports for all major entities
- **Audit Logging**: Full change history for critical entities

## Tech Stack

- Django 5.1
- Django REST Framework
- PostgreSQL (UUID primary keys)
- Redis + Celery for background tasks
- JWT authentication (djangorestframework-simplejwt)
- django-guardian for object-level permissions
- django-simple-history for audit logging
- WeasyPrint for PDF generation
- drf-spectacular for OpenAPI documentation

## Prerequisites

- Python 3.11+
- PostgreSQL 15+
- Redis
- Docker & Docker Compose (optional, for containerized deployment)

## Setup

### 1. Virtual Environment

```bash
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
```

### 2. Install Dependencies

```bash
pip install -r requirements/base.txt
```

For development:
```bash
pip install -r requirements/dev.txt
```

### 3. Environment Variables

Copy `.env.example` to `.env` and configure:

```bash
cp .env.example .env
```

Key variables:
- `SECRET_KEY`: Django secret key
- `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`: PostgreSQL settings
- `REDIS_URL`: Redis connection URL
- `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND`: Celery broker settings

### 4. Database Setup

**PostgreSQL is required** (see `DATABASE_SETUP.md` for details).

#### Quick Setup with Docker (Recommended):
```bash
# Start PostgreSQL and Redis
docker-compose up -d db redis

# Wait a few seconds, then run migrations
python manage.py migrate
python manage.py createsuperuser
```

#### Manual PostgreSQL Setup:
1. Install PostgreSQL 15+ (or use Docker)
2. Create database: `CREATE DATABASE academy_crm;`
3. Update `.env` with database credentials
4. Run migrations: `python manage.py migrate`

**Note**: SQLite is only available as emergency fallback with `USE_SQLITE=True` (not recommended).

### 5. Run Development Server

```bash
python manage.py runserver
```

The API will be available at `http://localhost:8000`

## API Endpoints

### Authentication
- `POST /api/v1/auth/login/` - Login (get JWT token)
- `POST /api/v1/auth/refresh/` - Refresh JWT token

### Public Endpoints
- `POST /api/v1/applications/` - Submit application
- `GET /api/v1/certificates/verify/{serial|qr_token}/` - Verify certificate

### Student Portal (`/api/v1/me/*`)
- `GET /api/v1/me/` - Get profile
- `GET /api/v1/me/enrollments` - Get enrollments
- `GET /api/v1/me/attendance` - Get attendance records
- `GET /api/v1/me/assessments` - Get assessments
- `GET /api/v1/me/grades` - Get grades
- `GET /api/v1/me/certificates` - Get certificates

### Admin Endpoints
All CRUD operations for Programs, Courses, Cohorts, Sessions, Applications, Enrollments, Assessments, Grades, Certificates, Documents.

### Lecturer Endpoints
- `GET /api/v1/my/cohorts` - Get own cohorts (explicit endpoint)
- `GET /api/v1/my/sessions?date_from=...&date_to=...` - Get own sessions (with date filtering)
- `POST /api/v1/attendance/bulk` - Bulk mark attendance
- CRUD for Assessments and Grades (own cohorts only)

### Certificate Endpoints
- `GET /api/v1/certificates/eligibility/{student_id}/{cohort_id}/` - Check certificate eligibility
- `POST /api/v1/certificates/issue` - Issue certificate(s) (bulk or single)
- `POST /api/v1/certificates/{id}/revoke` - Revoke certificate
- `GET /api/v1/certificates/verify/{serial|qr_token}/` - Public verification

### Enrollment Management
- `GET /api/v1/enrollments/waitlist/` - Get waitlisted enrollments (admin only)
- `POST /api/v1/enrollments/bulk_activate/` - Bulk activate enrollments (admin only)
- `POST /api/v1/enrollments/{id}/activate` - Activate single enrollment
- `POST /api/v1/enrollments/{id}/withdraw` - Withdraw enrollment
- `POST /api/v1/enrollments/{id}/complete` - Mark enrollment as completed

## Key Workflows

### Application → Enrollment Flow
1. Public submits application via `POST /api/v1/applications/`
2. Admin reviews and accepts application
3. Admin creates enrollment via `POST /api/v1/applications/{id}/accept`
4. Admin activates enrollment via `POST /api/v1/enrollments/{id}/activate`

### Session Generation
1. Admin creates cohort
2. Admin generates sessions via `POST /api/v1/cohorts/{id}/generate-sessions` with pattern (e.g., "TUE,THU"), start/end times, and holiday exclusions

### Attendance Marking
1. Lecturer opens session roster
2. Lecturer bulk marks attendance via `POST /api/v1/attendance/bulk` with session_id and list of student records

### Certificate Issuance
1. System checks eligibility (80% attendance + 60% weighted grade)
2. Admin issues certificates via `POST /api/v1/certificates/issue` (bulk or single)
3. PDF is generated with QR code pointing to verification endpoint

## Permissions

- **Admin**: Full access to all endpoints
- **Lecturer**: Read/write access to own cohorts, sessions, assessments, grades
- **Student**: Read-only access to own data via `/me/*` endpoints

Object-level permissions are enforced via django-guardian.

## Production Deployment

1. Set `DJANGO_ENV=prod` in environment
2. Configure `SECRET_KEY`, `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`
3. Set up Sentry DSN for error tracking
4. Configure email backend
5. Use production database and Redis
6. Run migrations: `python manage.py migrate`
7. Collect static files: `python manage.py collectstatic`
8. Use gunicorn or similar WSGI server

## Notes

- WeasyPrint requires system dependencies on Linux/macOS. On Windows, it may not work without additional setup.
- Time zone is set to `Asia/Tbilisi` (UTC+4)
- All datetime fields are stored in UTC, displayed in local time
